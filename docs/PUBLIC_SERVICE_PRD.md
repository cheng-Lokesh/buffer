# Buffer 公开服务与双端一致 PRD

日期：2026-10-07。依据：用户明确批准公开服务与双端一致，并确认统一账号、自动跨端同步、首发免费。状态：实施需求，公开服务尚未实现；不是上线完成证据。发布基线仍为 v0.35.0。

最高产品合同为 `docs/V12_1_PRODUCT_CONTRACT.md`，新方向以 `docs/PUBLIC_SERVICE_AND_PARITY_SCOPE.md` 为准。现有前端只从 `site/` 演进，不复活旧产品与旧前端。

## 1. Executive Summary

### Problem Statement

现有产品是独立本地存储的网页与小程序，无法让公众以同一账号跨端持续使用。小程序的交互、解析与模拟能力落后于当前网站，不能以已有核心测试通过宣称完整双端一致。

### Proposed Solution

在现有现金现实模型与视觉基础上，建立统一身份、按账号隔离的确认事实存储和自动同步；两端共用计算与确认规则，并补齐同一功能清单。首发免费、不接支付或订阅，先完成受保护验收再分阶段公开。

### Success Criteria

以下为开发验收目标，均未作为已完成指标：

1. 纳入首发的功能清单，双端完成率100%；同一输入、事实、时区、日期和模拟条件，预测金额（到分）、边界日期、确认结果完全一致。
2. 两端在线、请求成功且网络无异常时，服务器确认写入后另一端自动显示同一版本；测试目标95%的更新在5秒内可见。测量环境及样本数在同步实现验收方案中固定，不能拿延迟目标冒充实测。
3. 所有跨账号读、写、导出、恢复、解析上下文与绑定攻击测试均拒绝越权；已确认数据泄漏为0。
4. 断网重试、重复提交、并发修改和恢复失败测试中，已确认事实丢失及重复记入为0；冲突未解决不得覆盖数据。
5. 首发支付入口、订阅授权和用户扣款调用均为0；所有必测核心路径通过，未关闭的阻断发布缺陷为0。

## 2. User Experience & Functionality

### User Personas

面向需要了解当前可用现金、收入不稳定时的未来变化和主动模拟假设的个人用户。此处是目标场景，不是招募成果、真实用户画像研究或活跃度证据。产品不提供投资、借贷或消费行动建议。

### User Stories and Acceptance Criteria

**身份与接续使用**：作为用户，我希望网页版和小程序认出同一个账号，以便接着看自己的数据。

- 首次使用只选择一种受支持的登录方式；网页身份与微信身份关联必须验证双方控制权，不能按昵称、头像或客户端传来的身份自动合并。
- 登录失败、取消、过期都有可恢复路径；切换账号和退出后不能残留上一账号的现金、备份、待确认事实或同步队列。
- 身份供应商与具体登录方式TBD，不能把私有站点共用密码当作个人账号系统。

**现实确认与自动同步**：作为用户，我希望确认一次变化后两端自动看到，以免重复输入。

- 自然语言/语音先转为候选；本人确认后，代码校验并以一次原子事务提交。解析、预览、定位图表与模拟均不得写Reality。
- 两端取得服务器确认的版本后重新计算预测，不把预测或模拟线同步为现实。
- 断网明确显示本机待同步状态；只对已确认操作排队。重连自动重试，同一操作重复发送不会重复写入。
- 并发修改返回冲突，不静默采用最后写入覆盖现金；用户看到差异并明确确认后再提交。

**查未来与模拟**：作为用户，我希望在任意一端查某天余额、查余额对应日期和比较假设，以便理解未来变化。

- 两端都有今天、7天后、30天后快捷查询，以及预测范围内的月份/日期选择。
- 金额查询取首次预计余额不高于目标金额的日期；无命中保持当前选中点并说明。负余额、上升再下降、跨年和范围改变均须测试。
- 图表比例、日期、金额与点位解释来自同一数据；触摸与键盘只是不同控件，不改变查询意义。
- 固定收支、单次事项及受支持的多变化模拟与保存/读取草稿应两端一致；不以只保留小程序每日支出模拟替代网站现有能力。

**旧数据、备份与隐私控制**：作为已有用户，我希望安全接入账号并保留原数据，以免迁移丢失。

- 不自动上传旧数据。先导出本机备份，展示迁移范围与去向，由本人确认后上传；本机与云端均有数据时先展示冲突，不自动整份覆盖。
- 网页schema 9与小程序现有结构经适配进入共同语义，保留原始备份和历史含义；非法、过大、未知未来版本备份拒绝，不写部分数据。
- 两端提供同范围的导出、恢复、删除和账号数据控制。删除在服务器完成后传播到其他端，旧离线队列不得再次复活已删除数据。

**免费使用与降级**：作为用户，我希望知道免费范围和不可用原因，以免出现意外扣款或功能假装成功。

- 首发不接支付或订阅，不展示付费诱导；免费对用户不等于运营零成本。
- AI调用按账号与服务总预算配置上限，达到额度停止新调用并解释；精确输入、余额确认与可用的本地计算继续工作。
- 不展示不存在的语音/解析能力；权限拒绝可以回到完整文字路径，但不能把永久缺失功能写成双端验收通过。

### Non-Goals

不接支付或订阅，不开通未批准的付费云资源；不提供财务建议、自动执行、AI Chat、新一级空间、OCR或银行同步。不上线模拟身份、假同步或不隔离的数据服务；不通过降低网页版功能来达成双端一致。

## 3. AI System Requirements

### Tool Requirements

沿用服务端模型适配与严格`ParserInterpretation`语义，两个客户端调用同一版本的解析服务。供应商密钥只在服务端；请求上下文按已认证账号最小化，不接受客户端声明另一用户身份读取上下文。模型无业务写权限、无真实ID选择权限；确认后的服务端代码仍必须校验授权、精确金额/日期、版本与候选，原子提交。

语音仅转写，走同一候选链；转写实现TBD，禁止绕过本人确认。原始输入、模型输出与临时候选不默认长期保存或进入备份。

### Evaluation Strategy

- 复用并扩展已有语言安全夹具；模型理解、代码验证、用户确认和写入分别测试。
- 两端对同一候选确认得到相同事实；验证否定、条件变化、相对日期、余额锚点、Scenario混合、模糊金额、歧义、超时及拒绝权限。
- 拒绝跨账号上下文和伪造候选；原始提示、密钥、token和真实财务内容不进入日志、截图或公开Git。
- 本次已有历史模型评估仅是回归基础，新身份与公网边界必须重新验收，不能引用旧50例报告直接宣称公开安全通过。

## 4. Technical Specifications

### Architecture Overview

拟定逻辑：网页/小程序 → 各自身份适配 → 统一账号会话 → 认证与数据隔离 → 共享校验/确认事务 → 账号下确认事实与版本 → 两端同步缓存 → 同一规则重新计算预测。

网站保留`site/`与`server/site-server.mjs`默认入口。共享规则应有一个权威源码并输出浏览器与微信可用格式，视图按平台适配；不复制维护两套算法。两端使用同一服务器基准时区Asia/Shanghai与基准日期；预测在确认事实版本上生成，不以本机时区漂移改写记录。

同步协议需要`schemaVersion`、`revision`、`baseRevision`、由代码生成的幂等操作标识、已确认操作与删除世代。服务器从验证会话确定所属账号，不信任客户端owner字段；使用版本检查、去重和事务。协议是实现目标，当前并无该同步接口。

冲突与离线要求：先保持已确认本机副本，写入有待同步标识；重试不重复计入；冲突返回双方版本并保持原数据。退出/切换账号撤销会话并隔离缓存、队列；删除世代阻止旧设备或队列复活数据。初始迁移是专门的本人确认动作，不是首次登录的隐藏副作用。

登录/数据库/转写供应商不在本PRD中假定已有免费可用配额。用户免费、运营预算和资源授权分别处理；实际金额、额度及账单预警TBD。没有凭据或外部资源不应阻止共享逻辑和本地接口测试，但不能用内存服务器冒充生产持久化服务。

### Security & Privacy

公开上线前逐项复核适用法律、运营主体、域名/备案、平台与AI服务要求；本PRD是产品技术要求，不是法律意见或“绝对合规”承诺。

身份验证、账号数据隔离、传输保护、最小权限、CSRF/会话攻击防护、撤销、认证接口限流、解析总预算、隐私告知、授权与数据生命周期都需实现并验证。客户端缓存避免跨账号残留，服务端日志只保留必要诊断、不保留财务正文或敏感凭据。用户能查看、导出、删除自己的数据；操作须处理离线副本、备份恢复和账号绑定的影响。

当前私有站点与用户数据持续受保护。不能先开放再补数据隔离，不能把CORS、网页按钮隐藏或可猜的用户标识当作授权机制。

## 5. Risks & Roadmap

### Phased Rollout

1. **需求与差距清单**：本文件记录确认决策与源码现状；核实运营主体、真实AppID、登录/数据库资源和费用上限，版本号待后续确定，不更改当前已发布身份。
2. **共同规则与小程序补齐**：建立共享规则输出及完整一致性矩阵；补日期/金额查询、复杂解析、模拟、视觉与错误恢复。开发候选不等于微信真机通过。
3. **账号与同步**：通过认证/隔离/冲突/删除/迁移测试后接入实际持久化服务。先在受保护环境验证，不移除现有门禁。
4. **发布验收**：网页线上、微信工具与真机逐项执行同一清单；检查安全、免费成本保护、合规适用事项、故障恢复和旧数据迁移。缺失外部条件标记BLOCKED，不能伪造PASS。
5. **分阶段公开**：经过发布确认后开放；支持暂停新用户/AI调用和版本回退，不把业务免费做成无限运营开销。

### Technical Risks

- 免费对用户不等于云与模型免费，错误额度策略可能产生运营扣费。
- 网页身份与微信身份误绑定会暴露财务数据，必须验证控制权而非猜测映射。
- 两端本地结构、日期和模型能力不同，不能依靠截图相似替代语义一致。
- 并发余额锚点、旧离线队列、删除后恢复可能损坏确认事实，必须有版本/事务与明确冲突处理。
- 平台凭据、真机、域名、托管和主体条件未齐备会阻止发布；不得编造或绕过。
- 原有全库历史检查与新定位不完全匹配。只按明确产品决策修订需求检查，保留现实安全、备份、迁移和隐私检查，不削弱业务验收。
