# 账单导入后的产品设计：隐私优先版本

> 状态：2026-09-24 本人已授权其中的本机 CSV、仅本次查看私有试用子集；具体已实现范围与未完成项以 `BILL_IMPORT_PRIVATE_PILOT.md` 为准。本文其余内容仍是设计提案，不是法律合规证明，也不替代 `docs/V12_1_PRODUCT_CONTRACT.md`。

## 一句话方案

仅供本人使用。本人从原平台自行导出账单，在浏览器中手动选择文件；浏览器本地解析、清理和汇总，不把原始文件或交易明细上传到 Buffer、腾讯云函数、模型服务或分析服务。账单只回答“导入范围内已经发生什么”，不能自动改写本人确认的余额、条件和未来预测。Buffer 仍然“负责反映，不负责指导”。

这套设计旨在降低中国大陆上线试用的法律与隐私风险，不能承诺“绝对不会触碰法律”。是否需要备案、个人信息告知与单独同意、委托处理约定等，取决于最终部署地点、实际运营主体和数据流；正式开放前必须按实际实现重新核查。

## 产品边界

| 首版提供 | 首版不提供 |
| --- | --- |
| 本人手动导入自己有权使用的账单文件 | 输入支付平台、银行账号或密码；爬取网页、调用未获授权的私有接口；自动同步 |
| 导入前预览、字段检查、交易核对、删除某批导入 | OCR、截图识别、邮件自动读取、云端原始文件留存 |
| 导入范围内的收支、分类、较大单笔、近期交易 | “异常消费”评判、消费评分、投资或预算建议、行动指令 |
| 分离展示账单观察、本人确认的 Reality、已有 Forecast | 用交易汇总推断当前余额、用历史日均自动替换最低日支出、自动创建固定条件 |

不引入第五个一级空间，不改变现有夜空视觉。账单导入是将来单独批准的新能力，不伪装成现有“恢复备份”。

## 完整使用链路

1. 在“记录”中进入“导入账单”。入口说明“仅从本机选择文件；原文件不会上传”，同时有可打开的隐私与数据处理说明。未完成本地解析、安全存储和删除能力前，不显示可操作的导入入口。
2. 本人选择从原平台自行导出的受支持文件。浏览器本地检查格式、大小和日期；不向服务器发送文件内容、文件名、交易字段或浏览器事件分析数据。无法识别时只给出错误原因，不上传文件求助模型。
3. 预览识别到的来源、日期范围、交易条数、收支金额、被剔除字段和待核对项目。明确标注“这只是选中文件的范围，不代表全部收入或支出”。本人决定“仅本次查看”或“保存到本机”，取消即清除临时数据。
4. 对转账、充值、提现、退款、交易失败、重复导入、未知方向和同额疑似重复，先放入“待核对”。程序可以提示候选类别或重复原因，但不静默合并，也不把它们纳入“消费”统计。本人可逐条更正或排除。
5. 本人确认后，账单区域更新“已导入范围内”的统计。这一步仅确认交易整理结果，不等于确认当前余额或未来条件。后者仍走现有独立的 Reality Capture 确认链。
6. 随时可删一笔或整批导入、清空全部账单数据；对应观察统计立即重算或消失。删除账单不删除本人先前独立确认的 Reality。若需跨设备使用，由本人主动导出加密账单备份；首版不提供云同步。

## 四个空间的信息安排

### 现在

现有“当前余额、可使用金额、可支撑时间、保留金额”与现金结论保留为首屏主视觉，来源仍是本人已确认的 Reality。账单接入后，增加视觉上独立的“账单观察”组件，最多显示：

- 已导入范围：来源和起止日期；不写“本月全部账单”，除非本人明确确认覆盖完整。
- 已核对支出、已核对收入、净变化：金额相邻显示统计窗口和来源。
- 近期较大单笔、支出最多的至多三个已知类别、待核对数量：点击可进入“记录”的对应筛选。商户名默认不在首屏出现。

没有账单时整组组件不出现；不显示虚构的零值、空排行榜或不能使用的入口。若信息量超出一屏，只压缩次要明细的默认展示，不能缩小关键金额文字。账单组件不得与“未来 7／30／60／90 天预计余额”共享同一视觉标题。

落位沿用当前页面：顶部四张现金卡、中央夜景现金结论、右侧最近更新均不移动；在现有底部六张信息卡的**同一位置**加入“预计节点／账单观察”切换。默认仍展示现有预计节点；仅有可核对账单时出现第二个切换项，账单视图最多六张卡，不额外向下堆一整屏。手机保持相同信息顺序，以可读文字优先，不强制把桌面一屏要求套到窄屏。

### 未来与条件

首版不改预测输入和结果，不叠加“按账单支出推算”的第二条预测线。条件页也不自动生成固定收入、固定支出或最低日支出候选。若本人发现账单反映了持续变化，应通过已有入口自行更新并确认条件。

### 记录

明确分为“本人已确认的变化”和“本机导入的账单”两个视图。前者维持现有 Reality 时间线；后者按日期、来源、收支、类别、核对状态筛选，展示单笔金额、日期、类别、必要的说明，以及“仅来自本机导入”的状态。两类记录不合并成一条未经标注的时间线。原始账号、完整交易流水号、对方姓名和联系方式默认不显示，也不作为搜索索引。

## 指标的诚实口径

| 指标 | 条件与口径 |
| --- | --- |
| 当前余额 | 仅本人最后确认的现金锚点。导入不会覆盖或加减。 |
| 已导入支出／收入 | 仅在所选文件的起止日期、来源和已核对交易范围内汇总。未知、失败、疑似重复、转账、充值、提现先单独列示。 |
| 净变化 | 上述已纳入收入减支出，不等同于账户余额变化；多账户之间的资金移动不算收入或消费。 |
| 近期较大单笔 | 明确给出日期、金额与来源。它不是“异常”判断，也不暗示欺诈或不理性消费。 |
| 类别排行 | 仅在类别已核对时展示；未知类别单独列示，不从商户名猜测消费目的。 |
| 日均支出 | 首版不展示。导入来源和日期覆盖常不完整，直接除以 30 容易造成误导。 |
| 未来余额、可支撑时间 | 继续仅由已确认 Reality 与现有确定性计算生成；不得因导入账单自动变化。 |

所有摘要旁都显示“账单观察”及覆盖日期。未导入、未核对、数据不完整分别呈现，不把未知写成 0。

## 数据流与安全约束

本人选文件 → 浏览器内解析 → 字段最小化 → 本地预览／核对 → 本机受保护的存储 → 本机计算观察统计。账单数据不进入 Buffer 云端、DeepSeek、统计分析服务或现有 `cashReality`；除非本人另行走独立的 Reality 确认链。

- 原文件只在选择时读取，不上传、不缓存原文件、不放入普通产品备份。只保存展示与去重所必需的规范化字段：本地标识、日期、金额、方向、来源、经核对的类别、交易性质和核对状态。完整金融账号、实名、联系方式、地址、备注原文、完整流水号默认丢弃；必要时只保留末位脱敏信息。
- 为避免跨来源重复，使用本机生成的盐对必要交易标识做不可直接反查的摘要；相同金额／日期仅提示疑似重复，由本人决定。退款保留与原交易的关联，不把退款当作普通收入。
- 不把规范化交易写进现有未加密的 `localStorage` 或明文恢复快照。持久化方案须在实施前选定并通过安全验证；若加密存储尚未完成，只提供“仅本次查看”，刷新后不保留交易。
- 不加载可接触账单页面内容的第三方分析或脚本；避免将账单字段写入 URL、错误日志、遥测、截图、剪贴板或模型输入。字体等页面资产尽量自托管，网络请求须实测。
- 允许本人删除单笔、整批和全部账单，并可下载本人数据；明确说明浏览器清理数据、换设备及卸载时的丢失风险。加密备份若实施，应独立于现有 Reality 备份并由本人持有解密凭据。

## 告知、备案与上线闸门

本设计按“运营者可能属于个人信息处理者”的较严格口径设计，即使产品永久只有一位真实用户，也不把单用户当成当然豁免。若最终仅是本人处理自己的家庭数据，具体法律适用可能不同；云服务、外部模型和网站运营仍须按真实数据流判断。

在任何真实账单进入产品之前，至少完成以下闸门：

1. 核实网站是否属于中国大陆互联网接入服务，及现有 ICP／其他适用备案状态；本机预览与互联网部署分别判断。
2. 公布清晰易懂的处理规则：主体与联系方式、账单字段、用途、是否只在本机、保存期限、删除和导出方法、实际第三方及处理地域。若适用敏感个人信息规则，对金融账户信息的处理另作必要性说明并取得所需的单独同意；不以一枚默认勾选框替代。
3. 实测浏览器网络面板、云函数、服务商日志和备份，证明原始账单与明细没有外传；如最终确需上传，则停止沿用本方案，重新做安全与个人信息保护影响评估、第三方约定及告知同意设计。
4. 验证恶意 CSV／公式注入、超大文件、损坏编码、XSS、重复与退款、批次删除、设备丢失、导出恢复；没有相应安全和删除能力，不开放真实账单导入。
5. 仅继续私人试用，不因本文件推出面向公众的产品。若要公开、收费或扩展金融业务，重新做资质、备案、隐私与 AI 服务适用性评估。

## 依据与判断范围

- [《中华人民共和国个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)：最小必要、告知、敏感信息、权利、影响评估和个人／家庭事务例外。
- [国家网信办个人信息政策法规问答（2026 年 1 月）](https://www.cac.gov.cn/2026-01/09/c_1769688003183197.htm)：金融账户与消费、收入信息的识别。
- [《网络数据安全管理条例》](https://www.cac.gov.cn/2024-09/30/c_1729384452307680.htm)：安全措施、委托处理、删除与自动化采集。
- [《小型个人信息处理者个人信息保护简化措施规定》答记者问](https://www.cac.gov.cn/2026-07/24/c_1786638889576451.htm)：小规模可采用简化方式，但敏感信息保护仍在。
- [《非经营性互联网信息服务备案管理办法》](https://wap.miit.gov.cn/zcfg/xxtxl/art/2024/art_7e48434c08c24131b4b7eecfca5b2b6c.html)：境内互联网网站备案边界。
- [《金融信息服务管理规定》](https://www.cac.gov.cn/2018-12/26/c_1123908386.htm)：金融市场信息服务的适用定义；普通个人现金记录是否属于其他持牌业务，必须依最终功能判断。
