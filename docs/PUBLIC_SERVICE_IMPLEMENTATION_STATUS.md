### 后续私钥接入与兼容修复

已从本人指定的本机下载文件取得私钥，确认环境匹配；在受 Git 忽略的 `.secrets/cloudbase-custom-login.json` 保存副本，目录关闭继承权限，仅当前 Windows 账号及 SYSTEM 访问。原下载文件保留。没有输出、提交或上传私钥，也未进行 CloudBase 平台登录。

根因：原签名适配仅允许RSA2048以上，但腾讯云官方 CreateCustomLoginKey 文档说明生成RSA1024私钥。新默认仍要求2048以上；只有服务端显式选择 `keyPolicy: 'cloudbase-rsa1024'` 才兼容恰好1024位。更小/中间尺寸、非RSA、环境不符及未知策略继续拒绝。1024兼容是平台约束，不代表其具有2048位的安全强度；不默认启用公网服务，生产身份方案仍须安全复核。

官方来源：https://cloud.tencent.cn/document/product/876/130046

按 hunt 先定位、按 TDD 先执行并提交 RED：c3f7b8b（签名5项中2失败），b28519f（组合5项中1失败）；b1d85a2 GREEN。`npm run test:public-auth` 实际重跑27/27、exit0，覆盖率行100%、分支96.27%、函数100%。测试验证1024需显式选择、RSA签名可验证、未知策略/弱尺寸拒绝，以及组合传递策略。扫描该模式发现仅签名工厂与其运行时调用，均已修复；未扩张修改视觉。

本人真实私钥通过本地随机挑战签名/公钥验证，仅输出通过布尔值，没有签发测试账号的真实登录票据，也没有发往网络。因此这是文件和密钥校验 PASS，不是平台验票 PASS。仍缺 AppSecret、专用PG连接、平台登录和真实数据同步验收。私钥保管就绪不表示运行中的服务器已加载凭据。
