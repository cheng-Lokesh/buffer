# Buffer 公开服务与双端一致：定位决策

决策日期：2026-10-07。来源：用户明确要求“修改定位，接下来我们朝着公开服务推动。并且双端要完全一致”。

本文件记录已确认的定位和实施选择，正式实施需求见 [`PUBLIC_SERVICE_PRD.md`](PUBLIC_SERVICE_PRD.md)。需求不是公开上线批准或完成证据。现有发布版本仍为 v0.35.0，**尚未完成公开发布**。

## 已确认的变化

- 产品由本人私有使用，转向面向公众的个人现金状态与未来模拟服务。
- “永久单用户、只允许私有服务、V12.1 完成后不得推进后续产品”的限制不再约束本次已授权方向。
- 双端一致是正式交付要求，不接受功能缩水的小程序或只有相似截图的网页版。
- 最高原则不变：缓冲区负责反映，不负责指导。四空间与已确认现实、预计事项、预测、模拟的边界不变。
- 旧备份、迁移链、用户数据和未提交文件必须保留；网站继续以 `site/index.src.html`、现有素材与交互为视觉基线，不整体换风格。
- 不虚构真实使用、招募结果或活跃人数；自动化测试数据必须明确为测试夹具。

## 双端一致的验收定义

1. **功能一致**：现在、未来、条件、记录，以及现实输入、候选核对、确认、模拟、日期/余额查询、记录、备份和恢复，在两端完成相同任务。复杂自然语言解析及语音若纳入正式能力，不得只在一端提供或用假按钮替代。
2. **计算一致**：同一输入、同一确认事实、同一时区、同一基准日期和同一模拟条件，两端得到相同余额、边界日期、预测点位与事件解释。计算与校验采用共享规则和跨端测试，不维护两套独立语义。
3. **流程一致**：相同的入口意图、事实核对、成功反馈、错误恢复和撤销边界；不能一端自动写现实、另一端需要确认。
4. **信息与视觉一致**：继承网站现有视觉基线、中文文案、语义颜色和信息层级；适配桌面与原生手机控件，不要求不同屏幕像素位置相同。控件适配不得成为删减能力的理由。
5. **数据权利一致**：统一账号与跨端自动同步已经用户确认；两端访问同一账号下的确认事实，具有相同的查看、导出、恢复与删除范围。当前代码仍是本地存储和手动备份，不能宣传自动同步已存在。
6. **发布一致**：两端以同一功能清单验收，未完成项目必须显式标记；不能将现有网页单端测试当作微信真机或跨端验收。

## 公开服务前必须通过的门禁

- 明确运营主体、首发区域、托管方式、真实小程序 AppID 和平台发布条件；针对实际服务复核适用的备案、隐私、AI 服务及平台要求。不得以一句“不提供建议”或部署成功替代审查，不承诺绝对合规。
- 实现与所选存储方案匹配的数据隔离、访问控制、最小数据处理、隐私告知和数据删除/导出。公开服务不等于公开用户现金、备份或解析输入。
- 模型密钥只存服务端；实现适用于公众的防滥用、额度和成本保护、超时、限流与降级。现有单用户限流不能直接冒充多用户安全能力。
- 数据导入/迁移先预览并由本人确认；若增加服务器写入，同样必须验证、授权与原子提交。不得后台默默上传原有浏览器数据。
- 完成网页线上全流程、微信工具编译与真实手机操作、跨端一致性、数据隔离及迁移/恢复验收。
- 制定版本回退、故障恢复和分阶段开放方案。公开上线前继续保留现有腾讯云整站密码保护，不直接开放当前私有解析入口。

这些是待完成的产品门禁，不代表代码已有这些能力。

## 已确认实施选择

- 用户2026-10-07答复“是”，确认上一条消息中的两项建议：统一账号、跨端自动同步；首发免费、不接支付或订阅。

- 账号与同步的授权不等于同意把已有浏览器/小程序数据直接上传；旧数据进入账号前仍需展示范围并由本人确认。

运营主体、登录与数据库供应商、费用上限、域名和真实小程序 AppID 尚待核实（TBD）。可开发不依赖付费资源的共享逻辑与接口边界；不能默认上传数据或提前更改线上访问保护。
