## 首屏版式校准

四空间曾同时叠加外层装饰头部与动态页面顶部留白，桌面端标题实际从约 `209.6px` 才开始；动态标题又受到旧 Flex 高度约束，空间不足时会被压缩到 `0px`，造成“未来”页范围控件与副标题视觉重叠。

本轮建立统一的纵向节奏变量，并完成以下校准：

1. 桌面端装饰头部缩短为 `76px`，动态页面顶部留白为 `18px`，四空间标题统一从约 `114px` 开始。
2. 动态页面改为自然内容高度，标题不再被网格压缩；页面自身承担纵向滚动，后续内容不再被视口裁掉。
3. 主标题上限从 `58px` 收敛到 `50px`，保持视觉锚点的同时让状态控件更早进入首屏。
4. 手机端星空过渡区从 `210px` 收敛到 `176px`，页面头部保留 `38px` 环境空间，操作按钮恢复自然宽度并与正文左缘对齐。

## 右侧内容轨修复

用户截图暴露出“现在、未来、记录”多个页面的右栏宽度、留白与换行同时失衡。根因不是各页面分别缺少间距，而是左侧导航使用了无作用域的全局 `aside` 选择器：

1. 桌面端内容网格给右栏预留约 `398px`，但嵌套的内容 `<aside>` 被全局规则强制为 `190px`，形成窄卡片与右侧空洞。
2. 手机端同一泄漏又把内容 `<aside>` 强制为 `76px` 高，存在内容被挤压或裁切的风险。
3. “接下来已知”的空状态仍沿用有日期、名称、金额时的三列网格，导致“暂无额外已知事项”被塞进第一窄列并过度换行。

修复将导航样式限定到 `#uiwrap > aside`，并为桌面右侧内容轨建立统一的 `270–320px` 宽度。摘要标签左对齐、数字右对齐且不折行；“最后确认”说明紧随摘要；空状态使用单列标题与说明。手机内容栏恢复自然高度，保留正常纵向浏览。

RED 证据：`1920×1080` 下网格右轨为 `398.156px`，实际“现在”右栏仅 `190px`，回归测试失败。GREEN 证据：桌面三类右栏均处于 `270–320px`，没有水平溢出；手机内容栏不再继承 `76px` 导航高度；视觉密度验收 1 / 1 PASS；真实浏览器复核 1920×1080 的“现在、未来、记录”与 375×812 的“现在”PASS；控制台 0 errors / 0 warnings。
