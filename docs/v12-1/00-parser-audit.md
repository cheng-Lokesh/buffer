# Buffer V12.1 当前 Parser 审计

审计基线：`v0.34.0`，`8cdcc7aaa63e13757439cd94348258794a385839`

## 结论

v0.34.0 的 `deterministic-local-v12` 是规则和正则表达式 parser，不是通用自然语言 AI。它正确建立了“解析不得写入 Reality、候选必须验证、用户确认后才提交”的安全边界，但不能承担 V12.1 的复杂中文理解目标。

## 当前调用链

`RealityCapturePanel` 在组件内部固定创建 `createDeterministicRealityParserAdapter()`，再把它传给 `parseRealityMessage()`。因此所有自然语言输入都只经过本地规则。现有 `server/worker.js` 提供账户、同步、反馈和支付相关接口，没有 LLM 代理端点，也没有模型密钥边界。

## 当前规则能力

`deterministicParse()` 依赖以下显式规则：

- `如果 / 假设 / 要是 / 万一 / 假如`，整句直接归为 Scenario。
- `可能 / 也许 / 或许 / 大概 / 不一定`，整句直接要求澄清。
- `下个月 N 号 + 每月 + 工资 + 阿拉伯数字`，新增固定收入。
- `以后 + 房租 + 改成/变成/涨到 + 阿拉伯数字`，更新唯一房租条件。
- `工资 + 到账/到了/收到`，匹配到期工资或创建一次性收入。
- `房租 N`，创建一次性支出。
- `押金 + 退/返还 + N`，创建一次性收入。
- `现在/余额 + N`，创建余额锚点。

金额提取只识别阿拉伯数字及逗号，不能可靠理解“一千五”“八千六”“一万二”“2 万 5”等中文口语金额。日期仅有“下个月 N 号”一类手工逻辑。

## 固定句式依赖

下列能力只有命中固定顺序或关键词才成立：

- 金额必须紧邻特定词语，词序变化可能失败。
- “工资到了”的金额只从“但是/只有/实际/到账/到了 + 数字”中提取。
- 房租只按“房租 + 数字”处理，无法理解“房东刚扣走一千五”。
- 押金只按“押金 + 退/返还 + 数字”处理，无法稳定处理倒装、代词和多笔同额事项。
- 任何出现假设词的混合句都会整句变成 Scenario，明确 Reality 部分也丢失。
- 任何出现不确定词的混合句都会整句变成 clarification，无法部分成功。

## 无法可靠处理的真实人话

- 多事实和余额锚点：`房东刚扣我1500，我妈转2000，现在一共6700。`
- 中文金额：`工资扣完之后实际到手八千六。`
- 指代与延期：`之前那笔三千客户说周五再给。`
- 条件结束：`我辞职了，下个月开始没有这份工资。`
- 只确认最终余额：`昨天乱七八糟花了些，现在只剩4368。`
- Reality 与 Scenario 混合：`工资8500到了，如果以后涨到12000会怎样？`
- 明确与模糊混合：`押金1300退了，客户3000可能周五给。`
- 否定：`工资没到账。`、`没有取消工资。`
- occurrence 与 condition：`这次房租不用交。` 和 `以后都不用交房租。`
- 自然相对日期：`月底`、`下周五`、`三天后`、`下个月15号`。

## 规则组合爆炸风险

当前方案如果继续扩张，需要为词序、同义词、否定、时态、中文金额、相对日期、指代、多事实组合分别增加规则。每增加一个语义维度都会与既有维度交叉，造成规则数量和误判风险呈组合增长。尤其是先做全句关键词判断，会让 Scenario、Uncertain 和 Reality 混合句无法部分成功。

## 可保留部分

- `validateRealityCandidates()`、`previewRealityCapture()`、`commitRealityCapture()`。
- Balance Anchor、Atomic Commit、provenance 和用户确认。
- 本地 parser 仅保留为极保守 Fast Path、离线回退和确定性测试 fixture。
- LLM 只输出语义解释，真实 ID、候选映射、验证和写入继续由程序掌握。

## V12.1 必须改变

`RealityCapturePanel` 不再固定使用规则 parser。复杂输入必须进入服务端 LLM adapter，返回严格 Schema 后再经过本地确定性 Semantic Resolver。模型不得获得任何写入函数或真实业务 Tool。
